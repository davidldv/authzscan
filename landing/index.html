The problem

Authenticated ≠ authorized.

Most access-control bugs aren't "no login." They're a logged-in user reaching other people's data — an endpoint fetches orders/[id] keyed only on the client-supplied id, with no WHERE userId = session.user. User A reads User B's order.

Deciding whose data a query returns needs reasoning about the code, not matching syntax — which is why Semgrep, Snyk, and Copilot largely miss this class.

How it works

A four-phase pipeline. Only two phases call the model.

1 · Inventory
Enumerate every route handler & Server Action, detect the auth library, extract the repo's ownership idioms. Deterministic — ts-morph.
2 · Trace
Follow each client-controlled id to the DB query it reaches; flag queries with no ownership scope. Claude agent.
3 · Verify
Adversarial second pass — re-read the code, kill false positives, confirm only real "A reaches B" paths. Claude agent.
4 · Render
Markdown, SARIF 2.1.0, or JSON, plus a CI exit code. Deterministic.
The proof

Measured against a benchmark, not vibes.

A Next.js app with 16 seeded IDOR/BOLA vulnerabilities (6 easy / 6 medium / 4 hard) plus 6 hardened twins that act as false-positive tripwires. Zero label leakage — no // VULN markers to grep.

  • Result: pending eval — recall (found / 16) and precision (true positives / all confirmed), mean ± stddev across runs.
  • Gates: ≥ 80% recall, ≥ 70% precision.
  • A PerfectRunner oracle must score 1.0 / 1.0 — proving the harness is correct independent of model quality. The live eval scans a copy with the answer key removed.
